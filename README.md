# EnergyPulse (прототип)

Програмний засіб моніторингу та прогнозування енергоспоживання. Python, Streamlit, SQLite, scikit-learn, XGBoost, власна реалізація LSTM на NumPy.

## Запуск у Replit
1. Створіть Repl (Python), завантажте всі файли з архіву, збережіть структуру папок.
2. У Shell: `pip install -r requirements.txt`
3. Запуск: кнопка Run або `streamlit run app.py --server.port 8080 --server.address 0.0.0.0`
4. Перевірка ядра без інтерфейсу: `python selftest.py`

Облікові записи (створюються при першому запуску): `admin / admin123`, `manager / manager123`.
Це демонстраційний рівень захисту; для зміни паролів задайте змінні середовища `ENERGYPULSE_ADMIN_PASSWORD`, `ENERGYPULSE_MANAGER_PASSWORD` до першого запуску.

## Що реалізовано
- База даних: п'ять таблиць схеми «зірка» (Dim_Time, Dim_Object, Dim_Model, Fact_Consumption, Fact_Forecast) у SQLite, файл `energy_pulse.db`. Скрипт для MS SQL Server: `schema_mssql.sql`.
- ETL: CSV/Excel, довгий та широкий (BDG2) формат, файл погоди, звіт перевірки якості.
- Підготовка ознак: календарні, свята, лагові, ковзні, температура.
- Моделі: базовий метод, Random Forest, XGBoost, LSTM. Багатокрокова оцінка (MAE, RMSE, MAPE) на ковзних початках прогнозу, вибір основної моделі за RMSE, запис у Dim_Model і Fact_Forecast.
- Режими: погодинний (1-24 год) і добовий (7-30 діб).
- Аномалії: z-оцінка добових сум, залишки прогнозу, Isolation Forest; запис позначок у Fact_Consumption.is_anomaly.
- Звіти та рекомендації (правила на основі профілю, тренду, прогнозу, аномалій), експорт HTML/TXT.
- Ролі: адміністратор (імпорт, об'єкти, користувачі, база) та енергоменеджер.

## Важливі обмеження (чесно)
- Застосунок НЕ працює з MS SQL Server: структура відтворена в SQLite. Скрипт `schema_mssql.sql` не виконувався на сервері.
- Демонстраційні дані синтетичні. Результати дослідження потрібно отримувати на реальних даних (наприклад, BDG2).
- Імпорт широкого формату BDG2 перевірено лише на штучному файлі такої ж структури, не на оригінальних файлах набору.
- Свята: лише фіксовані дати (див. calendar_utils.py).
- LSTM реалізовано на NumPy (без TensorFlow), невелика мережа; точність нижча, ніж у Keras-варіанта, що тренується довше.
- Запуск у Replit автором архіву не перевірявся (середовище без доступу до мережі); ядро та сторінки перевірено локально з заглушками інтерфейсу.
